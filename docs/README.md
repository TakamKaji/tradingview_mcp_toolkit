# ドキュメント

[利用者マニュアル一覧](user/README.md)から必要な操作を参照できます。

## 開発・配布の流れ

1. `main`を正本とし、最新のmainから短命の作業ブランチを作成します。
2. 修正内容に応じた確認を行い、main向けPRを作成します。mainへの直接pushは行いません。
3. PRのレビュー後、承認された変更をmainへ反映します。
4. 利用者はmainの **Code → Download ZIP** からGitHub標準のソースZIPを取得・展開します。Windowsでは展開先の`setup.bat`を実行します。

バージョンタグとGitHub Releaseは、必要な場合にだけ発行します。通常の配布にタグやReleaseは必須ではありません。`develop`ブランチは廃止済みです。

配布内容の確認では、必要なファイルとリンクが揃い、認証情報・runtime・個人の結果ファイル・開発用の生資料が混入していないことを確認します。専用ZIP生成ツールは使いません。
