# 自然言語スクリーニング受入：配布用main

## 目的と対象

**リポジトリの通常配布`main` ZIPを3つの新規フォルダに展開**し、初見のGemini CLI・Codex CLI・Claude Codeに同じ自然言語を送って、入口選択・実行・結果の意味を独立検証する。開発資産を含む`develop`ではなく、`main`のZIPを使う。`main`へ配布版文書を同期したこと、静的ファイルを確認したこと、**各AIの実機セッション**および**TradingViewのOAuthが成功したこと**は別々の受入条件。

### 判定A：日経225とSMA25（Read-only）

AIには新規セッションで、次の本文**だけ**を最初に渡す（事前に方式・列名・ファイルを指定しない）。

> このフォルダの使い方を理解して、このツールを使って日経225採用銘柄の中から25日移動平均線との乖離率が+20%以上の銘柄をスクリーニングするスクリプトを作成し実行してください。

- 必須：READMEとAI入口、Schema・利用者ガイドを自発的に読んだ根拠。
- 対象：公式Providerの検証済み日経225 `symbolset:["SYML:TVC;NI225"]`、stock指定で**全225件**が取得されるか実測。`filters.index:"nikkei 225"`へ代用しない。
- 取得：公式MCPを自作直結せず、**本リポジトリのラッパーまたは標準CLI**を使用。必要な`close`/`SMA25`のnull、非数値、重複と基準日を検査。
- 乖離率：`(close/SMA25-1)*100>=20`。現行のProviderに未確認の乖離率filterを捏造しない。単一JSONで足りない**取得後の計算**だけを理由付きで追加する。Python専用の新CLI/認証クライアントは作らない。
- 終了条件：実行コマンド、stdout/stderr、終了コード、出力ファイルの絶対/相対パス、結果行数、総件数・評価/未評価件数、保存時刻、現物日足の確定状態、失敗・欠損理由を報告。**生成しただけ・Schemaが通っただけでは成功にしない**。
- 欠落した場合は正しく`PARTIAL`または`BLOCKED`。Watchlist/Alert Write、Scheduler登録/削除は**不可**。

### 判定B：東証プライム全件（安全な非代用）

初期状態へ戻した別の新規フォルダ・新規セッションで、次だけを渡す。

> このフォルダの使い方を理解して、このツールを使って東証プライム全上場銘柄から25日移動平均線との乖離率が+20%以上の銘柄をスクリーニングするスクリプトを作成し実行してください。

- 必須：Primeの正確な市場所属と全件網羅の検証可能な出所を確認する。
- 不可：TOPIX/日経225/TSE全体/上位1000件/手書き代表銘柄をPrime全件の代理にする。`market_segment=Prime`・無検証のindex/symbolsetを有効と断定しない。
- 原則：全件の検証済み母集団が用意できなければ、**適切な理由でBLOCKED/未達と報告するのが正解**。別の出所によるPrimeリストが法的・技術的に利用可能で、全件照合できた場合のみ次段階へ進む。
- 仮に部分取得を行ったら「全プライム対象の完全結果」と名乗らず、実際の範囲・差分・失敗理由を明示する。

## 実行環境と隔離

1. GitHubの`main` **Code → Download ZIP**を取得。新しいフォルダへ3回展開（`trial-gemini`/`trial-codex`/`trial-claude`）。各AIは自分のフォルダだけを作業領域とする。配布以外の開発用ファイル・既存の`results/`・`runtime/`を持ち込まない。
2. Windowsでは各フォルダで`setup.bat`から認証・実行環境を整備。Dockerでは[Docker利用手順](DOCKER.md)に従う。秘密情報・OAuthトークンはログや報告へ記載しない。
3. 各フォルダのルートで`gemini`、`codex`、`claude`をそれぞれ起動する。各CLIがそのホストにインストールされ、ログイン済みであることを事前に確認。コマンド不在・ログイン不可は**環境BLOCKED**でありツールの合否にしない。
4. A/Bケースごとに**新しいセッション・独立したフォルダ**で同じプロンプトを与える。モデルへの追加入力や人の介入が必要になったら記録して**初見一発合格とは判定しない**。
5. 出力は各フォルダの生成物をそのまま保存。実行ログ・起動時に読んだ指示ファイル、コマンド・戻り値と新しい結果のタイムスタンプを残す。`results latest`だけを証拠にせず実行前の結果時点と照合。

## 合否・結果記録

| 項目 | PASS | PARTIAL / BLOCKED / FAIL |
| --- | --- | --- |
| パッケージ | main ZIP内に必要な起動/Schema/マニュアルあり | 必須ファイル欠落、開発版を参照 |
| AI入口 | 自分でルートの規則・実ファイルを読んだ証跡あり | 未確認・説明だけ |
| ケースA | Provider全件、列検証、計算、出力保存、実行ログすべて確認 | 全件未検証、結果未実行など |
| ケースB | Prime未確定を正しく説明して止める、または検証済み母集団で完全実行 | TOPIX等へ無断変更、欠落隠し |
| 副作用 | TradingView Readとローカル保存のみ | Watchlist/Alert WriteやScheduler変更 |

実行報告には **検証main SHA、AI製品/バージョン、OS、起動時刻、使用したコマンド、取得件数、出力パス、判定と理由**を残す。秘密値やProvider生応答全文は公開しない。

### この文書の作成時点での判定

- **Windowsの別展開フォルダでTradingView OAuth・Providerデータ取得**：ここでは未実施。
- **Gemini/Codex/Claudeのそれぞれの新規CLIセッション実行**：ここでは未実施。エージェントが実装・実行した証跡が存在するまで`PASS`と記録しない。
