# 自然言語スクリーニング受入：配布用main

## 目的と対象

**リポジトリの通常配布`main` ZIPを3つの新規フォルダに展開**し、初見のGemini CLI・Codex CLI・Claude Codeに同じ自然言語を送って、入口選択・実行・結果の意味を独立検証する。取得したZIPが`main`のものであることを確認する。`main`へ配布版文書を同期したこと、静的ファイルを確認したこと、**各AIの実機セッション**および**TradingViewのOAuthが成功したこと**は別々の受入条件。

実装方式・データソース選択の正本は[AIによる方式選択フロー](AI_JSON_GUIDE.md#aiによる方式選択フロー)。以下はその判断規則を検証するケースであり、特定モデル専用の規則ではない。

### 判定A：日経225とSMA25（Read-only）

AIには新規セッションで、次の本文**だけ**を最初に渡す（事前に方式・列名・ファイルを指定しない）。

> このフォルダの使い方を理解して、このツールを使って日経225採用銘柄の中から25日移動平均線との乖離率が+20%以上の銘柄をスクリーニングするスクリプトを作成し実行してください。

- 必須：READMEとAI入口、Schema・利用者ガイドを自発的に読んだ根拠。
- 対象：公式Providerの検証済み日経225 `symbolset:["SYML:TVC;NI225"]`、stock指定で**全225件**が取得されるか実測。`filters.index:"nikkei 225"`へ代用しない。
- 取得：**標準Screening JSONと`app.bat screen <name>`を最優先**し、標準機能で取得できない部分だけ既存ラッパーを使用。公式MCPへの自作直結や不要な外部指数構成銘柄ファイルの取得は行わない。必要な`close`/`SMA25`のnull、非数値、重複と基準日を検査。
- 乖離率：`(close/SMA25-1)*100>=20`。現行のProviderに未確認の乖離率filterを捏造しない。単一JSONで足りない**取得後の計算**だけを理由付きで追加する。Python専用の新CLI/認証クライアントは作らない。
- 終了条件：実行コマンド、stdout/stderr、終了コード、出力ファイルの絶対/相対パス、結果行数、総件数・評価/未評価件数、保存時刻、対象の日足バーが確定済みであるか、失敗・欠損理由を報告。**生成しただけ・Schemaが通っただけでは成功にしない**。
- 欠落した場合は正しく`PARTIAL`または`BLOCKED`。Watchlist/Alert Write、Scheduler登録/削除は**不可**。

### 判定B：東証プライム全件（安全な非代用）

初期状態へ戻した別の新規フォルダ・新規セッションで、次だけを渡す。

> このフォルダの使い方を理解して、このツールを使って東証プライム全上場銘柄から25日移動平均線との乖離率が+20%以上の銘柄をスクリーニングするスクリプトを作成し実行してください。

- 必須：既存Provider機能と正本ガイドを確認し、公式MCPでPrimeの正確な上場区分と全件母集団を検証できるか調べる。将来の対応も実測・検証して判断し、永久に非対応とは扱わない。
- 不可：TOPIX/日経225/TSE全体/上位1000件/手書き代表銘柄をPrime全件の代理にする。`market_segment=Prime`・無検証のindex/symbolsetを有効と断定しない。
- 原則：公式MCPでPrime所属と全件母集団を検証できなければ、**適切な理由でBLOCKED/未達と報告して停止するのが正解**。JPX公式上場銘柄一覧は代替案として提示する。外部データ利用を明示的に選択・承認していないこの依頼では、JPX一覧の取得・導入や独自の外部母集団構築に進まない。外部一覧が検証済み・利用可能でも同じ。利用者が明示的に選択した場合は判定Cで扱う。
- 初回報告：追加質問を待たず、正本の[母集団が確定できない場合の初回報告](AI_JSON_GUIDE.md#母集団が確定できない場合の初回報告)に従い、全件取得実績がある近い代替候補を通常1〜3件提示する。日経225なら過去の225/225件の実績と出典・確認日、Prime全体との相違、基準日・網羅性と現在未確認の事項を添え、現在の取得保証とはしない。適切な国内候補を優先し、実績のある候補がなければ創作しない。**利用者の明示的な選択前には代替母集団で実行しない。**
- 仮に部分取得を行ったら元の全件依頼は`BLOCKED`、取得・評価済み部分は`PARTIAL`として停止し、「全プライム対象の完全結果」と名乗らず、実際の範囲・差分・失敗理由を明示する。未実行・未評価を該当0件と混同しない。

### 判定C：利用者がJPXデータ利用を明示的に許可

判定Bと同じ依頼に、次の許可を加えた独立ケースとする。

> 東証プライムの母集団にはJPX公式上場銘柄一覧を取得して利用してください。

- この明示的な選択の範囲で外部データの取得・利用を認める。利用者が外部ファイルを提供した場合も、その利用指示の範囲内で扱う。
- 正本ガイドの[データと失敗を追跡する](AI_JSON_GUIDE.md#データと失敗を追跡する)に従い、出典・基準日・全件母集団、TradingView symbolとの対応、欠損・重複・未照合、評価済/未評価件数、完全性を検証する。
- TradingViewデータ取得は標準JSON・CLIを優先し、不足する部分だけ既存ラッパーを利用する。全件を検証できなければ`BLOCKED`/`PARTIAL`とし、実行・保存結果の証跡とWrite・Schedulerの禁止は判定Aと同じ。

## 実行環境と隔離

1. GitHubの`main` **Code → Download ZIP**を取得。新しいフォルダへ3回展開（`trial-gemini`/`trial-codex`/`trial-claude`）。各AIは自分のフォルダだけを作業領域とする。配布以外の開発用ファイル・既存の`results/`・`runtime/`を持ち込まない。
2. Windowsでは各フォルダで`setup.bat`から認証・実行環境を整備。Dockerでは[Docker利用手順](DOCKER.md)に従う。秘密情報・OAuthトークンはログや報告へ記載しない。
3. 各フォルダのルートで`gemini`、`codex`、`claude`をそれぞれ起動する。各CLIがそのホストにインストールされ、ログイン済みであることを事前に確認。コマンド不在・ログイン不可は**環境BLOCKED**でありツールの合否にしない。
4. A/B/Cケースごとに**新しいセッション・独立したフォルダ**で各AIに同じプロンプトを与える。Cは最初から上記許可を含める。モデルへの追加の入力や人の介入が必要になったら記録して**初見一発合格とは判定しない**。
5. 出力は各フォルダの生成物をそのまま保存。実行ログ・起動時に読んだ指示ファイル、コマンド・戻り値と新しい結果のタイムスタンプを残す。`results latest`だけを証拠にせず実行前の結果時点と照合。

## 合否・結果記録

| 項目 | PASS | PARTIAL / BLOCKED / FAIL |
| --- | --- | --- |
| パッケージ | main ZIP内に必要な起動/Schema/マニュアルあり | 必須ファイル欠落、開発版を参照 |
| AI入口 | 自分でルートの規則・実ファイルを読んだ証跡あり | 未確認・説明だけ |
| ケースA | 標準JSON・CLI優先、225件の網羅性、列検証、必要な後処理、出力保存、実行ログすべて確認 | 全件未検証、結果未実行、不要な外部一覧取得など |
| ケースB | Prime未確定なら停止し、初回報告で実績のある近い代替母集団とJPX案を提示（候補がなければその旨を説明）。選択前には実行しない。または公式MCPで全母集団を検証して完全実行 | 候補の創作、過去実績を現在の取得保証とする、選択前の代替実行、未承認のJPX取得・外部母集団構築、TOPIX等へ無断変更、欠落隠し、未実行を該当0件扱い |
| ケースC | 明示的な許可の範囲でJPXを利用し、出典・基準日・銘柄対応・件数・完全性と実行・保存結果を確認 | 承認だけで全件確認を省略、欠損・重複・未評価を隠して成功扱い |
| 副作用 | TradingViewからのデータ読み取り（Read）とローカル保存、Cで許可された外部データのReadのみ | Watchlist/Alert WriteやScheduler変更 |

実行報告には **検証main SHA、AI製品/バージョン、OS、起動時刻、使用したコマンド、取得件数、出力パス、判定と理由**を残す。秘密値やProvider生応答全文は公開しない。

### この文書の作成時点での判定

- **GitHub上の`main`文書とSchemaの静的検査**：実施対象。静的検査は実行確認に代用しない。
- **Windowsの別展開フォルダでTradingView OAuth・Providerデータ取得**：ここでは未実施。
- **Gemini/Codex/Claudeのそれぞれの新規CLIセッション実行**：ここでは未実施。エージェントが実装・実行した証跡が存在するまで`PASS`と記録しない。

公式MCPのRead 246回は別系統で既に確認されたデータ能力調査であり、上記の自作ラッパーの受入成功件数には算入しません。
